## Password reset & invite emails (Supabase configuration)

The "Forgot password", admin "Reset password (email)", and "Invite user"
flows all rely on links generated by Supabase. For the links to land on
this app — instead of falling back to your project's Site URL — two
dashboard settings must be in place.

In the Supabase dashboard, under **Authentication → URL Configuration**:

1. **Site URL** — set to your deployed origin (e.g. `https://app.example.com`).
2. **Redirect URLs (allowlist)** — add each environment's reset/invite
   landing pages. Wildcards are allowed:

   ```
   https://app.example.com/reset-password
   https://app.example.com/*
   http://localhost:5173/*
   ```

If `/reset-password` is not in the allowlist, Supabase silently redirects
to the Site URL when the email link is clicked, which looks to the user
like "the reset link sent me back to the login page."

The edge functions also honour a `SITE_URL` environment variable when
generating recovery / invite links — set it on each function deployment
to the same origin as Site URL above.

### SPA routing on static hosts

The reset/invite links land on `/reset-password`, which is a client-side
React Router route. The repo ships fallback rewrites for the common
hosting platforms so direct hits to that path don't 404:

* `vercel.json` — Vercel
* `public/_redirects` — Netlify, Cloudflare Pages

If you deploy somewhere else (S3 + CloudFront, nginx, Apache, etc.),
configure an equivalent "serve `index.html` for unknown paths" rule.
